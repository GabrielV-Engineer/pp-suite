## Architect.PP (started 2026-10-26)

Scope and ownership decided: [architect-pp-scope](docs/architect-pp-scope.md). Architect.PP guides the design and checks it; SDD.PP
owns the plan. Done: the design linter rules `D01` to `D03` (tests, each broken on purpose; `D04`, an all-`must` warning, was removed on 2026-11-16); `ppc validate --design`; the hand-off command, tried twice on one real blueprint ([fixtures](architect-pp/fixtures/README.md)). Done too: the scope review (the person keeps or cuts each addition the tool made): `additions.yaml`, rules `X01` to `X05`, `ppc decide-addition`, the guard, the cut-applying prompt; tried once on the real fixture ([scope review](docs/scope-review.md)). Done too (2026-10-26): the tests policy (`test_policy` in the blueprint and per slice; rules `T16`, `W06`; a test debt is proposed when a slice closes without tests; `ppc overview` shows the verification line) and the per-task prompts (`ppc prompt`); both tested, neither measured against a control. Done too: the light cycle (`default_mode`, `mode`, phase `build`, rule `L06`, `/pp-build`), tested, not yet measured against the strict cycle. Done too: the install command (`ppc init`, pinned versions in `install/versions.json`), tried once from a bare repository against Spec Kit at the pinned commit. Done too: overlapping additions are decided together (`overlaps`, `ppc decide-addition A B`, `--alone`); the hand-off prompt that writes `overlaps` has not been run again. Done too: Architect.PP packaged as the Spec Kit extension `architect-pp` and installed by `ppc init`; the hand-off was run through the installed skill (third run). Done too: the constitution is derived from the design (`ppc constitution`), and a slice can ask for a design change (`ppc change-request`, `ppc decide-change`, `/pp-change`, `ppc apply-change`, rule `T17`), tried once end to end on the demo project (a model revised the design in 52 seconds for 0.25 USD, and stopped at a hand-written constitution instead of forcing it). Done too (2026-10-26, a simplification round): Spec Kit's `specify`, `plan` and `tasks` and the preset left the flow (`/pp-plan` plans the slices from the design); the generated views and rule `G01` were deleted; the constitution became a block in `CLAUDE.md`; debt lives in one file with `ppc schedule-debt`; `brief`, `glossary` and `evidence` are optional; the per-task prompts are offered by a skill (`/pp-build prompts`) and no longer restate the skills. First evidence on orientation: [orientation-check](docs/orientation-check.md). Done too: Spec Kit's `clarify`, `analyze` and `converge` were rewritten for this flow (`/pp-check clarify|analyze|converge`), each tried once ([review](docs/speckit-skills-review.md)); `ppc init --update` reinstalls stale extensions. Done too: the rules block in `CLAUDE.md` was cut from about 5,300 to about 1,300 characters (references, not copies) and a `SessionStart` hook shows the state at the start of every session ([orientation-check](docs/orientation-check.md)). Done too: a three-way test on the demo project (vibecoding, Spec Kit alone, pp-suite; [report](docs/e2e-test-report.md)) and, from it, two design-integrity checks: `C08` (a build does not edit `.architect/`) and `C09` (a slice changes only the files of its components, with optional `paths`). Not built: the experiment-3 harness, a command to mark stale slices as re-read, a real long-project trial.
